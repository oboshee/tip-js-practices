## Запуск

Рабочая папка: `practice-04` внутри личного репозитория. В PowerShell выполнение `npm.ps1` заблокировано политикой, поэтому используется `npm.cmd`.

```bash
npm.cmd test          # проверки сервиса и новых модулей
npm.cmd start         # локальный сервер
# или
node tools/serve.mjs
```

Устанавливать зависимости через `npm install` не требуется.

- Приложение (общий набор): http://127.0.0.1:5504/

Во всех проверках использовался один адрес `127.0.0.1:5504`: другой порт или имя узла — это другой origin и другое хранилище. Другие порты не использовались.

Пустое обязательное поле | Браузер покажет своё сообщение, обработчик `submit` не вызовется | События `submit` не было (счётчик 0), `validity.valueMissing = true`, журнал остался «Действия ещё не выполнялись.» | Нативная проверка `required` блокирует отправку до события `submit`; журнал не меняется |
| 2. Название из пробелов | Браузер пропустит, прикладная проверка отклонит | `submit` наступил, ошибка «Название не должно состоять только из пробелов.», журнал: «submit получен, но прикладная проверка отклонила значение.» | Строка из пробелов для `required` не пуста; после `trim` длина 0, ошибка ставится через `setCustomValidity` |
| 3. Типы значений `FormData` | `defaultPrevented: true`, значения — строки, название без краевых пробелов | `submit.defaultPrevented: true`; `typeof FormData title: string`; `typeof localStorage value: string`; сохранено `{"title":"Тест формы","priority":"high"}` (ввод был `"  Тест формы  "`) | `FormData.get` возвращает строки; `preventDefault` отменяет стандартную отправку; `trim` нормализует название |
| 4. Строка в `localStorage` и JSON | `getItem` вернёт строку JSON, `JSON.parse` — объект | Прочитана строка `{"title":"Тест формы","priority":"high"}`, `JSON.parse` вернул объект с полями `title` и `priority` | `localStorage` хранит только строки; объект восстанавливается через `JSON.parse` |
| 5. Повреждённый JSON | `JSON.parse` выбросит исключение | После записи `{broken-json`: «JSON.parse завершился ошибкой: Expected property name or '}' in JSON at position 1 (line 1 column 2)» | Некорректный синтаксис приводит к исключению, поэтому разбор помещается в `try/catch` |

## Организация кода

| Модуль | Ответственность |
|---|---|
| `src/data.js` | Исходные наборы `demoTasks`, `variantTasks`, номер варианта |
| `src/task-service.js` | Создание и неизменяющие операции над задачами, включая `updateTask` |
| `src/task-selectors.js` | `getVisibleTasks(tasks, filter)` — отбор по фильтру |
| `src/task-view.js` | Создание карточек, отрисовка списка, сводки и пустого состояния |
| `src/form-validation.js` | `validateTaskDraft` — чистая нормализация и проверка черновика формы |
| `src/task-storage.js` | JSON-оболочка `{ version, tasks }`, проверка схемы, чтение, запись, удаление ключа |
| `src/main.js` | Состояние (`currentTasks`, `currentFilter`, `editingId`), режим формы, события, координация модулей |

`validateTaskDraft` и функции хранения не обращаются к DOM; `renderApp` не читает и не записывает хранилище.

**Почему функции хранения получают объект `storage` аргументом.** Модуль не зависит от глобального `localStorage`: в проверках подставляется `MemoryStorage` (и объекты, выбрасывающие исключения), поэтому сбои чтения, записи и удаления воспроизводятся без браузера.

**Почему данные из JSON проверяются до использования.** Запись могла быть повреждена, изменена вручную или сохранена другой версией приложения. Корректный по синтаксису JSON не гарантирует нужную структуру, поэтому после `JSON.parse` проверяются версия и вся схема (`isValidTaskList`: безопасный положительный `id`, уникальность, название 1–100 символов после `trim`, `completed` — boolean, допустимый приоритет). При любой ошибке запускается копия исходного набора.

## Отладка и клавиатура

Точка останова в `handleFormSubmit` (`src/main.js`), добавление задачи `id = 20`:

| Что смотрим | Значение |
|---|---|
| Сырой `draft` | `{ id: "20", title: "  Изучить localStorage  ", priority: "high" }` (все значения — строки) |
| Результат `validateTaskDraft` | `{ ok: true, value: { id: 20, title: "Изучить localStorage", priority: "high" } }` — `id` приведён к числу, название нормализовано |
| Результат `addTask` | `ok: true`, добавлена `{ id: 20, title: "Изучить localStorage", completed: false, priority: "high" }`, `id` в списке: 1, 4, 7, 10, 20 |
| Строка JSON в Local Storage (`…:demo`) | `{"version":1,"tasks":[ … , {"id":20,"title":"Изучить localStorage","completed":false,"priority":"high"}]}` |

Ошибочный сценарий (повторный `id = 4`): `validateTaskDraft` вернул `{ ok: false, errors: { id: "Задача с таким идентификатором уже существует." } }`, поэтому `handleFormSubmit` вызвал `showFormErrors` и вышел до `addTask`; список и хранилище не изменились.

В режиме редактирования поле `id` заблокировано и в `FormData` отсутствует (`null`); `validateTaskDraft` берёт идентификатор из `editingId`, и `updateTask` меняет только `title` и `priority`.

**Клавиатура и фокус.** Все управляющие элементы нативные (`input`, `select`, `button`), поэтому доступны с клавиатуры, а порядок Tab совпадает с порядком в DOM.

- Нажатие Space на кнопке «Выполнить» меняет статус (выполнено 2 → 3), нажатие Enter возвращает его (3 → 2). После перерисовки списка фокус остаётся на кнопке `toggle` той же задачи (`restoreTaskFocus`).
- При начале редактирования («Изменить») фокус переходит на поле «Название».
- При отмене редактирования форма возвращается в режим создания, фокус — на поле «Идентификатор».

## Вывод

Реализована форма создания и редактирования задач на событии `submit` с отменой стандартной отправки. Нативные ограничения HTML дополнены чистой прикладной проверкой `validateTaskDraft`, не зависящей от DOM. Добавлена операция `updateTask`, сохраняющая `completed` и не изменяющая входной массив. Данные сохраняются в `localStorage` в формате JSON с версией; чтение проверяет всю схему и безопасно переходит на исходный набор при ошибках. Ключи общего и индивидуального наборов разделены, сброс удаляет только текущий ключ. Пройдены 35 проверок сервиса, 27 проверок новых модулей и 23 браузерных сценария, выполнены общий и индивидуальный сценарии.

Различие между проверками:

- **Нативная проверка HTML** (`required`, `maxlength`, `type="number"`) выполняется браузером до события `submit` и отвечает за структуру ввода.
- **Прикладная валидация** (`validateTaskDraft`) знает предметную область: нормализация `trim`, уникальность `id`, допустимый приоритет, границы длины.
- **Проверка данных после чтения из хранилища** (`isValidTaskList`) нужна потому, что `localStorage` — внешний источник: успешный `JSON.parse` не гарантирует корректную версию и схему, а повреждённая запись не должна ломать запуск.
