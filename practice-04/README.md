6. Форма, валидация и режимы
Форма обрабатывается через событие submit с event.preventDefault(), поэтому работает и отправка по Enter.
Два уровня проверки: HTML (required, min, step, maxlength) и прикладной (validateTaskDraft).
Ошибки выводятся рядом с полем (data-error-for), поле получает aria-invalid; при событии input ошибка этого поля очищается.
Режим создания: editingId === null, операция addTask.
Режим редактирования: поле id заблокировано (disabled) и в FormData отсутствует, поэтому идентификатор берётся из editingId; операция updateTask меняет только title и priority, completed сохраняется.
После успешной операции форма возвращается в режим создания.
7. Сохранение данных
Ключи: tip-js-practice-04:demo и tip-js-practice-04:variant; для страницы проверок — tip-js-practice-04:checks:*.
Формат записи: { "version": 1, "tasks": [...] }.
После чтения проверяются версия и вся схема задач (положительный безопасный id, уникальность, название 1–100 символов после trim, completed — boolean, приоритет low/medium/high).
Ошибка чтения, JSON, версии или схемы: запуск с копией исходного набора и предупреждением; повреждённая запись автоматически не удаляется.
Сброс удаляет только текущий ключ через removeItem и не записывает исходный набор обратно. localStorage.clear() не используется.
Ошибка setItem не откатывает изменение в памяти: пользователь получает предупреждение.
